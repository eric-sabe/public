Under the hood

Twenty centuries of sermons, one honest answer

Ask Athanasius answers questions from a corpus of Christian teaching — contemporary sermons and the Church Fathers alike — by retrieving the actual passages that speak to the question and generating an answer that cites every source it stands on. Nothing is asserted that can't be traced back to a text.

Private build · not yet deployed Python · FastAPI Next.js 16 · tRPC ~490k chunks · bge-m3 Ollama / Grok / OpenAI / Claude

The corpus

Four sources, one schema

Content arrives from very different places — YouTube transcripts, sermon manuscripts, web articles, and 19th-century markup — and leaves the pipeline speaking one language.

Redeemer

Sermon transcripts pulled from YouTube via yt-dlp and the transcript API

Wisdom International

Sermons and full manuscripts, scraped and standardized

Desiring God

Web articles parsed with BeautifulSoup and Playwright

CCEL — Church Fathers

Athanasius and company, via a custom parser for ThML — Theology Markup Language

Parse

Source-specific connectors; each implements just discover() and fetch()

Standardize

Source metadata mapped to one unified schema — speaker, book, work, passage

Chunk

2,000-char chunks with 400-char overlap, split at sentence boundaries

Vectorize

bge-m3 embeddings, 1024 dimensions, L2-normalized, batched

Store

MongoDB documents carrying both the text and its embedding, richly indexed

Design decisions

Chosen tradeoffs, stated plainly

DecisionWhyThe cost
Full-corpus in-memory retrievalEvery search scores all ~490k chunks — no pagination artifacts, no candidate cutoff hiding the right passage~2 GB of RAM and a few seconds of warmup, cached to disk after the first load
MongoDB instead of a vector databaseOne store for text, metadata, and vectors; metadata filters run in the same query as retrievalSlower than a dedicated vector DB — which is exactly what the in-memory matrix compensates for
Sentence-aware chunkingChunks end where thoughts end; retrieved passages read like prose, not fragmentsUneven chunk sizes; token counts vary against LLM context windows
Multi-provider LLM abstractionLocal Ollama for development, Grok/OpenAI/Claude in the cloud — swapped by environment variablePrompt behavior varies per provider; costs tracked per-model to keep it honest
LLM query preprocessing (optional)"Compare Athanasius and Piper on the Incarnation" becomes a structured plan: entities, filters, strategyAdded latency — so it's confidence-gated, and plain semantic search is the fallback
Citations post-processed, not prompt-engineeredAdjacent duplicate citations are collapsed after generation; works identically across all four providersNon-adjacent duplicates survive — a visible seam, honestly worn
By the numbers

Measured, not vibes

~490,000 chunks indexed 1024-dim embeddings (bge-m3) ~2 GB in-memory matrix <100 ms full-corpus similarity 2–15 s end-to-end (LLM-dominated) 5–10 s index warmup, then disk-cached

Cost is tracked per provider and per model — the pricing table is asserted at startup, so a misconfigured model can't silently log $0.

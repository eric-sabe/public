Under the hood

A sealed chamber for agent → human reviews

Team Airlock lets an AI agent publish an interactive review — an architecture decision, a spec, a punch list — to human reviewers, collect structured answers, and then make the whole package cryptographically unreadable, everywhere, in one operation. What survives is a signed receipt proving the review happened.

“Where your agent takes work to humans — and brings the answers back.”

The lifecycle

One package, six stations, no plaintext left behind

Every review package walks this line. Step through it — the dashed arc is what happens if the agent never comes back for the results.

The three guarantees

Sandbox, isolation, shred

1 · Enforced sandbox

The package can render, but it cannot reach

Agent-authored HTML runs in an opaque-origin iframe (sandbox="allow-scripts", never allow-same-origin) served from a separate, cookieless content origin. Its CSP says connect-src 'none' — no fetch, no XHR, no WebSocket, no beacon. The only way out is postMessage to a broker that validates every write against the package's inferred schema, deny-by-default. Author JavaScript never runs at all: rich UI comes from Airlock's own web components, rendered from declarative data.

2 · Tenant isolation

Postgres has the final word

Every row carries a subscription id, and row-level security is FORCEd — the app connects as a non-owner role and sets tenant scope per transaction. A bug in application code cannot cross tenants, because the database itself refuses. Reviewer magic links are HMAC-signed, single-use by unique constraint, and redeem atomically.

3 · Crypto-shred

One delete makes everything unreadable

Each package gets its own AES-256 key, wrapped by a KMS master and stored only in an unversioned S3 bucket with no backups. Content, responses, and attachments are all encrypted under it, bound to {tenant, package, revision} so stolen ciphertext can't be replayed elsewhere. The shred deletes that one wrapped key — and every copy of the ciphertext, in Postgres, S3, and Redis, becomes permanently inert at once. Not a best-effort cleanup — a structural guarantee.

What survives

Proof without plaintext

After the shred, retrieveResults returns 403 — there is no key to decrypt with. What remains is an append-only audit log and an HMAC-signed receipt: who was invited, what was answered (as a hash), when it was collected, when it was purged. Enough to prove the review happened; nothing that can leak what was said.

The stack

Built local-first, shaped for AWS

Phase 0 runs entirely on docker-compose — Postgres, Redis, MinIO, LocalStack-KMS, ClamAV — so the whole security model is testable on a laptop. The AWS shape (CloudFront + S3, Fargate, Aurora Serverless, KMS) is the same architecture with the toys swapped for the real things.
